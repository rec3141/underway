Camera runtime deployment

The app is self-contained. No icecamera checkout, Downloads directory, human-label portal, clustering, or historical processing queue is needed. Install the project's cameras extra for Pillow. Model inference requires a compatible local llama.cpp/Gemma runtime and NVIDIA tooling; unsupported CPU sensors fail closed.

Explicit worker activation

  1. Copy ice.json.example to the operator's ~/.config/underway/ice.json. Set the source, product root, existing Gemma weights/projector and llama-server paths. No automatic model downloads.
  2. Stop the development Gemma worker, watchdog, and shared server before reusing their port/GPU. Do not run two queue owners. Confirm crew chat uses the selected endpoint.
  3. Copy the example user units to ~/.config/systemd/user/underway-ice.service and underway-ice-model.service. Adjust Python and installation paths for the host.
  4. Run systemctl --user daemon-reload, then systemctl --user enable --now underway-ice.service. The first scan records its capture-time start boundary; it does not classify older photos. The persisted boundary catches up new photos after downtime. Never delete the database to resume.

Code merges do not automatically install or activate these optional user units. After later worker-code upgrades, explicitly restart the worker. GPU OOM is not cured by retries: unload competing models first.

Products and provenance

Default product root: /data/underway_server/ice. Override the web server with UNDERWAY_ICE_ROOT if needed. SQLite stores pending/filtered/Gemma rows, detailed responses and report-only audit alerts. JPEG source/ROI/slice derivatives are cached by opaque ID. The compact range API contains no model prompts or descriptions; photos are fetched on demand.

Filtered means estimated 0% ice; pending is null, never zero. The six type percentages sum to concentration; unknown is not ice. All percentages are exploratory. Browser requests neither start models nor read the camera share.

Historical data

Historical classification remains a dev responsibility. The explicit import command accepts completed results/skips only; it does not enqueue historical photos. Never copy the development selection.json into the production worker. Importing products is separate from new-arrival discovery.

Thermal and recovery behavior

CPU: 95°C trailing time-weighted 120-second average. GPU: 83°C cutoff; admission below 78°C. A cutoff stops the owned model service, waits for CPU <85°C, average <85°C and GPU <70°C, then retries later. A single-instance lock, atomic image publication, persistent pending rows and bounded request timeouts preserve progress. Filter audits only report; they do not disable filters or requeue skips automatically.
